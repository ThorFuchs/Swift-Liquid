## Security assessment

The historical inventory contains 115 variants from `security_drops.yml`.
They exercise Ruby method/instance-variable access, dispatch and reflection;
allowed methods; chains, assignment, control flow and filters; and conversion
of explicit Ruby objects to Liquid values. Ruby runtime identity and reflective
calls are not portable requirements. The transferable invariant is that an
unregistered host member cannot be discovered or invoked through Liquid lookup
or subsequent operations. The added public-API regression checks dot and
bracket access, conditions, assignment, filters and loops in all three parser
modes, and verifies the registered callback count. It also checks that an
explicitly registered name such as `class` is usable: this is an allowlist
boundary, not a reserved-name denylist. Existing tests cover dynamic-prefix
routing, callback counts, quotas and cancellation. An explicitly installed
indexer or dynamic family delegates its advertised keys to trusted host code;
it must enforce its own access policy. This Swift regression does not execute or
claim a match for the 115 excluded Ruby fixtures. Broader chained, array and
conversion cases need separate transport and invariant review.

The initial independent and reviewed attempts failed at SwiftPM manifest build:

combined candidate selector, with per-case checks for all additional fixture

old selection digest and must be reassessed for any changed selection. Preserve
raw and reviewed results separately, then compare every identity and classify
regressions, conflicts, failures and unexecuted cases separately. Retain durable
receipts and finish security review and release gates before any release decision.
