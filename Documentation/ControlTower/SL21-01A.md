upstream loader and have not been run in this increment. The new tooling is an
isolated inventory, selection and materialization probe; it is **not** wired to

run the existing full lane under the prohibition on fixture-supplied Ruby
execution. No additional Drop cases are admitted.

The five selected suites contain 72 YAML fixture files, 5,099 source cases and
5,112 parser-mode variants. The probe found two generated variants, 312 variants
with environment constructor markers, two template-factory variants, eleven
resource-limit variants and 57 variants with a filesystem `_error-message`.
There are no declared shared `data_files` or directory fixtures in these suites.
The two generators use the `n` and `n * n` interpolations in
`basics/drops.yml`; both remain excluded. The unrelated `#{1+1}` in
`basics/security.yml` is a literal Liquid test input, not a generator.

Execution and materialization paths requiring protection are:

- `SpecLoader.load_yaml_file` generates random values and calls `Binding#eval`
  on fixture interpolation before the current selector runs. `load_all` reseeds
  each suite with 15401. The new inventory neither draws random numbers nor
  interpolates the excluded generators, so its generator sequence is explicitly
  **not equivalent** to that historical loader. It only validates the two
  pinned shapes using `MethodDropMaterializer.bounds`.
- `LazySpec#deep_instantiate` resolves fixture `instantiate:` markers through
  `ClassRegistry` and calls registered factories. The current full driver calls
  `instantiate_environment` during preflight, and the upstream
  `AdapterRunner#run_single` calls environment, filesystem and template-factory
  instantiation again before compilation. The historical LongString admission
  also invokes that registry through `Admission.check`.
- The upstream JSON-RPC DropProxy can dispatch `public_send` for callbacks.
  The existing bridge rejects unexpected callback messages, but that boundary
  must be retained and tested in any new full runner. `AdapterRunner#load_dsl`
  can call `Kernel.load`, although this driver's configured path does not use
  that method. Selected templates execute as Liquid in both engines; they must
  not be interpreted as Ruby. Comparator regexes are patterns, not permission to
  execute Ruby source.
- YAML loading, aliases, built-in Date/Time/Range/Regexp values and parser-mode
  expansion are separate materialization boundaries. The inventory uses
  `Psych.safe_load` with only explicit built-in classes and limits, and installs
  an `eval` guard; it still constructs those built-in YAML values before
  eligibility. This is not a demonstrated full-path guarantee that *all*
  fixture constructors are deferred. Unknown shared data files, generated
  shapes, file populations and fixture fields fail closed in the probe.

## Evidence obtained

The new `fixture-inventory` CI lane uses the pinned checkout, historical matrix,
63 existing admissions and the 425-case review. It preserves modes, error policy,
source locations, feature tags and file digests. All 5,112 identities and their
recorded metadata match the earlier matrix. The earlier matrix had 488 holds;
its 63 later admission identities and the retained 425-case review partition
those exactly. Inert preflight reproduces 4,687 selected and 425 held identities,
including the original first exclusion reason for each held identity. It does
not change the published admission policy.

After selection, the probe prepares primitive environments and normalizes
filesystem names, with a closed, length-bound LongString policy. Against the
clean-source, checksum-verified **earlier** receipt at commit
`ff32be9df9dc32a41cd535e3db10ab13d88d28c4` (which had 488 holds):

- All 4,624 formerly selected cases match template and filesystem wire hashes
  and expected values from that earlier evidence.
- 2,648 of those match an environment wire hash. The other 1,976 have no
  historical render request, so environment fidelity is not established.
- The 63 cases admitted after that earlier run have no prior wire evidence in
  that receipt. Their materialization fidelity against the later historical
  425-hold run is unverified. The later full source-bound matrix and traces
  were not found in the available artifacts.
- None of the 425 held variants is materialized by the probe. These comparisons
  do not establish current raw or reviewed verdicts.

The lane checks eval-guard engagement with constant probes, rejects unknown
and changed generator shapes, changed LongString parameters, unapproved
constructors, oversized inputs, cycles, duplicate/missing identities and
changed input digests. Its callback sentinel checks an excluded fixture in the
isolated selector. These tests do not yet prove the same properties in a full
comparator run, nor do they add an end-to-end negative control for an expected
error masking an operational failure. Existing diagnostic and reviewed-conflict
checks remain separate.

## Remaining blockers

A safe preparation layer must be integrated into a full runner without changing
the comparator, selection or fixture bytes. It must make its constructor and
callback boundary enforceable throughout `AdapterRunner`, preserve nonexecuted
generator metadata without inventing results, and handle built-in YAML values
without violating eligibility ordering. The current raw and reviewed paths must
be kept separate; reviewed policy is bound to the historical eligibility digest,
including generated expectations. Do not normalize that evidence silently.
Obtain or explicitly account for the missing later historical traces, establish
all 5,112 before/after outcomes, add the remaining end-to-end adversarial checks,
and run the independent, reviewed, native, safety, documentation and adapter
lanes against a clean identified candidate. No merge, release or complete
conformance claim follows from this probe.
